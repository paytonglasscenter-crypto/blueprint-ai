## 1. Purpose

This document defines the first website build plan for Payton Glass Center.

The provisional recommended path is an Astro-based structured static website because it best supports:

- Fast performance
- Clean content structure
- Local SEO
- AEO/GEO/AI search readiness
- GitHub-based version control
- AI-assisted editing
- Reusable Blueprint AI methodology
- Future CRM and automation preparation

This plan does not start coding yet.

It defines what should be built, in what order, what content is needed, what must be confirmed before launch, and what should wait.

---

## 2. Core Principle

Build the website as a business system, not a brochure.

The first website should help customers understand, trust, and contact Payton Glass Center.

It should not attempt to become:

- A full booking system
- A full ecommerce store
- A full CRM
- A class platform
- A customer portal
- An automation hub

Those may come later.

The first website should create a strong public foundation.

---

## 3. Provisional Build Path

### Recommended Path

Astro-based structured static website.

### Why

Astro is a strong fit because it supports:

- Static performance
- Markdown/content-driven pages
- Component-based page sections
- Clean routing
- SEO metadata
- Image optimization
- Flexible future integrations
- GitHub-based workflow
- AI-assisted content operations

### Important Design Note

The public site should look like a professional local business website.

It should not look like a documentation site.

Blueprint AI and Starlight-style thinking should influence internal structure, not force a documentation-style visual interface.

---

## 4. Fallback Build Paths

### Fallback A: WordPress

Use if:

- Mark wants easier direct editing
- A non-technical person must manage the site
- Existing hosting strongly favors WordPress
- Speed plus familiar editing matters more than structured GitHub workflow

### Fallback B: Temporary Focused Launch

Use if:

- Current site is hurting the business badly
- A fast public improvement is needed before full structure is ready
- Owner data is incomplete but core positioning is strong enough
- The first version can launch with only Home, Group Tours, Contact, FAQ, and Visit

### Fallback C: Current Site Patch

Use only if:

- Access is easy
- The current platform is workable
- A quick update can reduce immediate damage
- Full rebuild remains planned

## 11. Content Build Workflow

Recommended workflow:

1. Create page structure.
2. Pull draft copy from `WEBSITE_COPY_DRAFTS.md`.
3. Replace placeholders with owner-confirmed data.
4. Remove unconfirmed claims.
5. Add SEO title and meta description.
6. Add headings and FAQ sections.
7. Add selected media.
8. Add internal links.
9. Add contact CTA.
10. Review for accuracy.
11. Review for local search alignment.
12. Review for AI-answer clarity.
13. Review for mobile readability.
14. Publish only after launch blockers are resolved.
