## 6. Website Build Decision Summary

The website build decision compared possible build paths:

1. Website builder
2. WordPress
3. Static site
4. Astro
5. Astro/Starlight-style structure
6. Custom React / Next.js
7. Current website refresh only
8. Hybrid temporary landing site plus later full build

### Provisional Recommendation

Build an Astro-based structured static website for the first serious rebuild.

### Reason

Astro best supports:

- Fast performance
- Clean content structure
- Local SEO
- AEO/GEO/AI search readiness
- GitHub workflow
- AI-assisted editing
- Future CRM/automation preparation
- Blueprint AI repeatability

### Practical Caution

The public website must look like a real business website, not a documentation site.

Starlight-style thinking may influence internal structure, but the customer-facing site should be designed for visitors, group organizers, families, schools, and local search.

### Fallback

WordPress remains the strongest practical fallback if visual editing and common small-business maintenance are more important than structured GitHub workflow.

## 10. CRM First Step Decision Summary

The CRM first-step decision compared possible customer-tracking options.

Options reviewed:

1. Email only
2. Email plus spreadsheet
3. Google Sheet
4. Airtable
5. Lightweight CRM
6. Full CRM
7. Custom CRM
8. No CRM yet

### Recommended First CRM Decision

Use a structured Google Sheet as the first CRM-style inquiry tracker, connected to the website inquiry form if practical.

### Why

Google Sheet first is recommended because:

- It is familiar.
- It is fast to set up.
- It does not slow down the website build.
- It can receive form submissions.
- It can track statuses.
- It can be reviewed manually.
- It can be improved before committing to CRM software.
- It allows Mark to learn what actually needs tracking.

### Secondary Recommendation

Move to Airtable if the workflow needs:

- Linked tables
- Better views
- Better event tracking
- Better pickup tracking
- Better class interest tracking
- Lightweight automation

### Do Not Build Yet

- Custom CRM
- Heavy CRM
- Full automation
- AI customer replies
- Online booking
- Payment automation

## 11. Phase 3 Major Conclusions

### 11.1 The Website Is the Next Primary Build

The next practical build target is the Payton Glass Center website foundation.

The site should become the public source of truth for:

- Customers
- Google
- Bing
- Apple
- AI search systems
- Social platforms
- Future CRM and automation

### 11.2 Owner Data Still Controls Launch Readiness

The site structure and copy are ready enough to build.

The site is not ready to launch until critical owner data is confirmed.

Critical data includes:

- Business name
- Address
- Phone
- Email/form destination
- Hours
- Active offers
- Group tour details
- Pricing decisions
- Capacity/age limits
- Pickup policies
- Minimum launch media

### 11.3 The First Build Should Be Focused

The first build should focus on:

- Clarity
- Trust
- Group tour conversion
- Structured inquiry capture
- Local search alignment
- AI-answer-ready content

It should not try to become a full operations platform on day one.

### 11.4 The First CRM Should Be Lightweight

The first CRM step should prevent lost opportunities without creating tool complexity.

Google Sheet first is the recommended starting point.

### 11.5 Automation Should Still Wait

Automation has been planned, but should not be built until:

- Inquiry workflow is tested
- CRM/tracker is stable
- Policies are confirmed
- Pricing/capacity rules are clear
- Follow-up patterns are observed
